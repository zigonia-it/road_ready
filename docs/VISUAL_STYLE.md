# Game Visual Style -- Modern Chunky Pixel

## 1. Core Visual Style

**Modern high-detail pixel-art game illustration style.**

Friendly, colorful and slightly exaggerated cartoon proportions with a
polished video-game aesthetic. Use clearly visible pixel-based
rendering, crisp hard-edged shapes and strong dark outlines around major
forms. Avoid photorealism.

Use a vibrant but controlled color palette with strong saturation, clear
separation between objects, and approximately **3--6 tonal values per
main color**. Lighting should be bright and readable, using simplified
highlights and layered cel-shaded pixel clusters rather than smooth
photographic gradients.

Shapes should be simplified and slightly exaggerated for readability.
Important features should be larger and clearer than realistic
proportions, while minor details should be reduced. Silhouettes must
remain immediately recognizable even when the asset is displayed at a
smaller size.

Use rounded, friendly forms combined with confident angular details
where appropriate. The overall mood should feel:

-   Optimistic
-   Playful
-   Energetic
-   Friendly
-   Modern
-   Suitable for a teenage audience
-   Appropriate for an educational adventure/driving game

Maintain the same visual language across characters, vehicles,
buildings, landscapes, traffic signs and environmental props.

### Key visual characteristics

-   Bold, dark outlines
-   Clearly visible pixel clusters
-   Crisp hard edges
-   Saturated but controlled colors
-   Simplified geometry
-   Slightly exaggerated proportions
-   Strong and readable silhouettes
-   Layered cel-shaded lighting
-   Clear separation between foreground elements
-   Friendly cartoon styling
-   High-detail modern pixel art rather than strict retro pixel art

------------------------------------------------------------------------

## 2. Avoid

Do **not** use:

-   Photorealistic textures
-   Photographic rendering
-   Painterly brushwork
-   Watercolor effects
-   Excessive micro-detail
-   Thin vector-style lines
-   Smooth 3D rendering
-   Blurry edges
-   Excessive/noisy dithering
-   Strict NES-era graphical limitations
-   Generic AI fantasy styling
-   Unrealistic glowing effects unless specifically requested
-   Unnecessary decorative elements that reduce readability

The result should look like an intentionally designed game asset, not an
image that has simply been passed through a pixel-art filter.

------------------------------------------------------------------------

## 3. Asset Background and Export

Unless otherwise specified:

-   Use a **true transparent background**
-   Do not render a checkerboard transparency pattern into the image
-   Do not add scenery behind isolated assets
-   Do not add text unless explicitly requested
-   Do not add an external drop shadow unless explicitly requested
-   Keep the entire asset inside the canvas
-   Leave reasonable transparent padding around the asset
-   Keep edges clean and suitable for use as a game sprite or game asset

------------------------------------------------------------------------

# Asset-Specific Guidelines

## 4. Characters

Characters should use slightly exaggerated cartoon proportions.

### Characteristics

-   Slightly oversized head
-   Large, expressive eyes
-   Clearly readable facial expressions
-   Simplified anatomy
-   Chunky clothing shapes
-   Strong silhouette
-   Expressive poses
-   Friendly and approachable appearance
-   Clear separation between limbs, clothing and accessories
-   Clothing details should use pixel clusters rather than tiny
    realistic textures

Characters should remain recognizable when scaled down.

Hero characters should generally appear:

-   Friendly
-   Positive
-   Confident
-   Curious
-   Approachable

Avoid making protagonists appear unnecessarily aggressive or
intimidating unless specifically required by the story.

------------------------------------------------------------------------

## 5. Vehicles

Vehicles should remain recognizable as real-world vehicle types while
being adapted to the game's visual universe.

### Characteristics

-   Recognizable real-world proportions
-   Slightly compact or exaggerated proportions
-   Wheels may be slightly larger than realistic
-   Strong wheel arches
-   Simplified body panels
-   Bold headlights
-   Clearly defined grille
-   Strong dark outline
-   Simplified reflections
-   Chunky pixel-based shading
-   Important vehicle features should be emphasized

Avoid photorealistic automotive rendering.

A vehicle should look like a purpose-built game asset rather than a
photograph converted into pixel art.

------------------------------------------------------------------------

## 6. Houses and Buildings

Buildings should be inspired by recognizable real-world architecture
while using simplified game geometry.

For Norwegian environments, preserve recognizable elements of Norwegian
architecture where appropriate.

### Characteristics

-   Simplified building geometry
-   Strong silhouette
-   Slightly exaggerated roofs
-   Clearly readable windows
-   Clearly readable doors
-   Reduced small architectural details
-   Chunky pixel shading
-   Bold outlines around major structural elements
-   Controlled texture detail

Do not draw every individual brick, roof tile or wood grain.

Represent these materials using larger pixel clusters and simplified
patterns.

------------------------------------------------------------------------

## 7. Landscapes

Landscapes should use layered, chunky forms rather than realistic
environmental rendering.

### Vegetation

Trees and bushes should use:

-   Large foliage clusters
-   Simplified branch structures
-   Layered tonal values
-   Clearly defined silhouettes

Do not render individual leaves.

### Terrain

Grass, dirt, rocks and mountains should use:

-   Simplified shapes
-   Chunky texture clusters
-   Limited tonal variation
-   Strong visual separation

### Depth

Use clear separation between:

1.  Foreground
2.  Midground
3.  Background

Atmospheric depth may be used, but the environment should remain
consistent with the crisp pixel-art aesthetic.

------------------------------------------------------------------------

# 8. Norwegian Traffic Signs

Traffic signs require special treatment because their **semantic meaning
must remain correct**.

The purpose is **not** to reproduce the source image pixel-for-pixel.

Instead, identify which Norwegian traffic sign the source represents and
redesign it as an asset belonging to the game's visual universe.

## Preserve

Always preserve:

-   Semantic meaning
-   Sign category
-   Essential symbol
-   Essential colors
-   Overall recognizable shape
-   Important regulatory information

The player should immediately be able to recognize which real traffic
sign the asset represents.

## Adapt

The following may be adapted:

-   Exact proportions
-   Border thickness
-   Symbol thickness
-   Small geometric details
-   Perspective
-   Mounting/post proportions
-   Pixel arrangement

Use:

-   Chunky pixel clusters
-   Strong dark outlines where appropriate
-   Simplified internal geometry
-   Clear visual hierarchy
-   Slight exaggeration for readability

### Critical instruction

> **Do not make a pixel-perfect reproduction of the source image. Treat
> the source only as a reference for what traffic sign it represents.
> Redesign the sign as a game asset using the established visual style.
> Preserve its semantic meaning, recognizable symbol, essential colors
> and sign category, but simplify and exaggerate its geometry for
> readability. Use chunky pixel clusters, strong dark outlines and
> simplified internal details. It should look like a traffic sign
> designed specifically for this game's world, not a photograph
> converted through a pixel-art filter.**

Traffic signs must still be sufficiently accurate to function correctly
in an educational driving game.

**Stylization must never change the traffic rule communicated by the
sign.**

------------------------------------------------------------------------

# 9. Roads and Environmental Props

Environmental assets include objects such as:

-   Lamp posts
-   Guardrails
-   Bollards
-   Traffic lights
-   Bus stops
-   Road barriers
-   Road markings
-   Street furniture
-   Fences
-   Benches
-   Trash bins
-   Utility boxes
-   Roadside vegetation
-   Construction objects

These should use:

-   Simplified geometry
-   Thick, readable silhouettes
-   Exaggerated important features
-   Consistent dark outlines
-   Chunky pixel shading
-   Limited small details

Objects should look as though they belong naturally in the same world as
the characters and vehicles.

Do not create realistic objects and simply place them inside a pixel-art
environment.

------------------------------------------------------------------------

# 10. Reference Image Conversion Rule

When using photographs, screenshots or real-world reference images, the
goal is **reinterpretation**, not conversion.

## Primary rule

> **Reinterpret the real-world reference as an asset belonging to the
> game's visual universe; do not merely pixelate the original image.**

The reference image determines:

-   What the object is
-   Important identifying characteristics
-   Functional details
-   Essential colors where relevant
-   Semantic information

The game's visual style determines:

-   Proportions
-   Simplification
-   Pixel structure
-   Outlines
-   Shading
-   Level of detail
-   Exaggeration
-   Overall presentation

------------------------------------------------------------------------

# 11. Consistency Rules

All assets should appear to belong to the **same game**.

When generating a new asset, compare it conceptually against existing:

-   Characters
-   Vehicles
-   Buildings
-   Signs
-   Environmental objects

The following should remain consistent:

### Outline weight

Major objects should use similar dark outline thickness relative to
their size.

### Pixel density

Avoid mixing extremely coarse pixel art with highly detailed near-vector
artwork.

### Lighting

Use a consistent general lighting philosophy:

-   Bright readable highlights
-   Clear midtones
-   Strong but controlled shadows
-   No photorealistic global illumination

### Saturation

Colors should be vibrant without becoming neon unless an asset
specifically requires it.

### Geometry

Favor simplified, slightly exaggerated shapes over realistic complexity.

### Readability

Gameplay readability takes priority over realism.

------------------------------------------------------------------------

# 12. Master Prompt

The following can be used as the base instruction when generating new
assets:

> **Create this asset in the established Modern Chunky Pixel game style:
> high-detail modern pixel-art illustration with friendly cartoon
> proportions, crisp hard-edged pixel clusters, bold dark outlines,
> saturated but controlled colors, simplified geometry, strong
> silhouettes and layered cel-shaded lighting. Important features should
> be slightly exaggerated for readability while minor details are
> simplified. Avoid photorealism, smooth 3D rendering, painterly
> textures, excessive micro-detail and generic AI fantasy styling. The
> result must look like an intentionally designed asset belonging to the
> same game world as the existing characters and vehicles, not a
> photograph converted through a pixel-art filter. Use a true
> transparent background unless an environment or scene is explicitly
> requested.**

------------------------------------------------------------------------

# 13. Core Design Principle

The visual identity of the game can be summarized by one rule:

> **Recognizable real-world objects, reinterpreted through a friendly,
> colorful, exaggerated and highly readable modern pixel-art game
> language.**

Accuracy determines **what the object is**.

The visual style determines **how the object is represented**.

Gameplay readability takes priority over exact physical proportions,
while semantic and functional information must remain correct.
